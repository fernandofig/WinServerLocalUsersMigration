# Windows Server user migration scripts

This repository contains a series of scripts that helps on the migration of users and groups between two Windows Servers, as well as filesystem permissions.

The scripts here are meant to be used for migration only of Local Users/groups on a Windows Server, NOT for Active Directrory Users/Groups.

The scripts do the following:

- `user-extractor.ps1`: Extracts all users in the server to a CSV file. The CSV will contain:
  - Username
  - Full name
  - Description
  - User SID
- `group-extractor.ps1`: Extracts all groups in the server to a CSV file. The CSV will contain:
  - Group Name
  - Description
  - Members
  - Group SID
  - Members user list (with each username separated by `|`)
- `import-users.ps1`: Imports users from the CSV generated by the `user-extractor.ps1` script.
- `import-groups.ps1`: Imports groups from the CSV generated by the `group-extractor.ps1` script.
- `match-users-sids.ps1`: Takes in the CSVs generated by the `user-extractor.ps1` script both in the source and destination server, and generates another CSV correlating the users in the CSVs, with the columns:
  - Username
  - Source Server SID
  - Destination Server SID
- `match-groups-sids.ps1`: Takes in the CSVs generated by the `group-extractor.ps1` script both in the source and destination server, and generates another CSV correlating the groups in the CSVs, with the columns:
  - Group
  - Source server SID
  - Destination Server SID
- `translate-icacls-sids.ps1`: Takes in the CSVs generated by both the `match-users-sids.ps1` and `match-groups-sids.ps1` scripts, as well as a SDDL file generated by the `icacls` Windows utility, and translates the SDDL from the `icacls` utility such that SIDs for both Users and Groups of the source server are replaced by the equivalent ones of the destination server.
- `batch-translate-icacls-sids.ps1`: Helper script for `translate-icacls-sids.ps1`. Takes the user and group correlation CSVs and a wildcard pattern (e.g. `*.sddl`), and runs `translate-icacls-sids.ps1` iteratively for each matched file, saving the translated files in a `translated` subdirectory of where each original SDDL file is located.
- `restore-icacls-permissions.ps1`: Takes as parameter a wildcard pattern of SDDL files (e.g. `*.sddl`), iterates over each matching file, executes `icacls /restore` on it, and outputs all results and execution details into a single consolidated log file.

## Execution plan

This is how the scripts above are meant to be used:

1. Execute `user-extractor.ps1` and `group-extractor.ps1` on the source server.
2. Move the CSVs generated by the scripts on the 1st step to the destination server. Then, on the destination server:
   - execute `import-users.ps1` on the user list CSV.
   - execute `import-groups.ps1` on the group list CSV.
   - the two scripts above should be executed in the order above (users and groups), as the `import-groups.ps1` script will also allocate users to Groups they belong, and so the users must already exist in order for this to work. However, the import-groups script will not abort if a user does not exist, though it will log a warning in the console.
3. After users and groups are created by the scripts above, still on the destination server, execute `user-extractor.ps1` and `group-extractor.ps1` to generate CSVs for users and groups created.
4. Execute the script `match-users-sids.ps1` passing as arguments the user list CSVs of the source and destination server.
5. Execute the script `match-groups-sids.ps1` passing as arguments the groups list CSVs of the source and destination server.
6. Execute the script `translate-icacls-sids.ps1` (or `batch-translate-icacls-sids.ps1` for multiple files matching a wildcard pattern) passing as arguments the CSV files generated in steps 4 and 5, and the SDDL file(s) generated by the `icacls` Windows utility (i.e. `icacls /save ...`).
7. Run `restore-icacls-permissions.ps1` in the target server passing the wildcard pattern matching the translated SDDL files (e.g. `.\restore-icacls-permissions.ps1 ".\translated\*.sddl"`) to restore permissions and log all results to a single log file.

## Command-line reference

### user-extractor.ps1
```powershell
user-extractor.ps1 <output_userlist_filename.csv>
```
### group-extractor.ps1
```powershell
group-extractor.ps1 <output_grouplist_filename.csv>
```
### import-users.ps1
```powershell
import-users.ps1 <input_userlist_filename.csv>
```
_Note: usernames in the CSV that are found to already exist in the target server are skipped._

### import-groups.ps1
```powershell
import-groups.ps1 <input_grouplist_filename.csv>
```
_Note: Groups in the CSV that are found to already exist in the target server are skipped._

### match-users-sids.ps1
```powershell
match-users-sids.ps1 <input_source_server_userlist_filename.csv> <input_target_server_userlist_filename.csv> <output_userlist_correlation_filename.csv>
```
### match-groups-sids.ps1
```powershell
match-groups-sids.ps1 <input_source_server_grouplist_filename.csv> <input_target_server_grouplist_filename.csv> <output_grouplist_correlation_filename.csv>
```
### translate-icacls-sids.ps1
```powershell
translate-icacls-sids.ps1 <input_userlist_correlation_filename.csv> <input_grouplist_correlation_filename.csv> <input_icacls_export_filename.sddl> <output_icacls_translated_export_filename.sddl>
```
### batch-translate-icacls-sids.ps1
```powershell
batch-translate-icacls-sids.ps1 <input_userlist_correlation_filename.csv> <input_grouplist_correlation_filename.csv> <pattern> [-OutputSubdirectory <dirname>] [-PathPrefixSearch <string>] [-PathPrefixReplace <string>]
```
_Example:_
```powershell
.\batch-translate-icacls-sids.ps1 users_corr.csv groups_corr.csv "*.sddl"
.\batch-translate-icacls-sids.ps1 C:\Migration\users_corr.csv C:\Migration\groups_corr.csv "C:\Migration\*.sddl" -PathPrefixSearch "D:\Shares" -PathPrefixReplace "E:\Shares"
```
### restore-icacls-permissions.ps1
```powershell
restore-icacls-permissions.ps1 <pattern> [<output_logfile.log>] [-TargetDirectory <path>] [-ContinueOnError <$true|$false>]
```
_Example:_
```powershell
.\restore-icacls-permissions.ps1 "*.sddl"
.\restore-icacls-permissions.ps1 "C:\Migration\*.sddl" "C:\Migration\restore_all.log" -TargetDirectory "D:\Shares"
```

## Notes

- In Windows it's not possible to extract Users passwords, and as such, the passwords for the users in the source server are NOT migrated. Users created in the target server are created with a temporary password, with the option "User must change password at next logon" enabled.
- All accounts and groups are exported by the `user-extractor.ps1` and `group-extractor.ps1` scripts, including Windows built-in ones - that's because, in addition to user-created users and groups, we need to also get the correlation of SIDs of built-in users and groups between the two servers in order to fully translate `icacls`'s SDDL file content. It's recommended to inspect the contents of the CSV files generated by these extractor scripts before proceeding in further steps; it may be necessary to remove some rows for certain accounts or groups in some cases.
- The `translate-icacls-sids.ps1` script expects the input SDDL file to be UTF-16 LE encoded, which should be exactly how the `icacls` utility generates it (and processes, on restore).
